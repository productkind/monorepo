# Technical Skills in the AI Era

## 1

Technical Skills in the AI Era (1/5)

One question I think about a lot nowadays: which tech skills do product managers and founders without a technical background still need in the AI era?

As coding agents can do more and more every day, the answer keeps changing. Right now, I see four areas of technical knowledge that can give you more confidence and also let you automate more with AI.

1. Setting up and understanding environments

AI agents have become awesome at writing code, but they still lag behind at setting up the environment that code runs in. If you learn what an environment looks like and how to set one up, you’ll be able to debug or experiment with complex applications, not just vibe-coded prototypes.

2. The tools developers and AI agents share

Developers use Git, GitHub, the command line, databases, and code editor every day, and so do AI agents like Claude Code. Knowing the basics lets you access your organisation’s codebases and build tools on your computer that automate a much wider variety of tasks than you could with just an AI chat assistant.

3. Knowing how AI tools work

If you understand what AI tools are capable of, what they’re good at and where they struggle, you can develop a deliberate strategy for getting high-quality outputs and setting up reliable AI automation workflows.

4. A few rules of thumb from software engineering

For example, make one small change, test it, then move on to the next. When something breaks, you know which change caused it.

## 2

Technical Skills in the AI Era (2/5)

Setting up a development environment can make you lose a lot of hair. It's also the part AI agents still struggle with.

That's why I think understanding environments is one of the most useful technical skills you can learn if you're a product manager or a startup founder who isn't a developer.

Say you want to find out why something isn't working in your product.

If you can run the application yourself, you can reproduce the problem, look at what's happening and ask an AI agent to help you find the cause.

You don't need to depend on an engineer for every step of that investigation.

It also lets you deploy apps that you created with AI tools for your end users, or give your AI agents a sandbox to work in.

A good sandbox lets you experiment with AI agents without worrying about breaking anything. It can also let them run continuously and keep your automations going when your laptop is closed.

Of course, setting up environments can be frustrating, especially the first few times. Once you understand how they work, you can debug and experiment with complex applications, not just vibe-coded prototypes.

## 3

Technical Skills in the AI Era (3/5)

When an AI coding agent breaks something that was working, Git is how you get the working version back.

That's one reason I think the tools developers use every day are worth learning for product managers and startup founders who aren't developers: Git, GitHub, the command line, databases and editors like VS Code. AI agents like Claude Code and GitHub Copilot use many of them too.

Git tracks every change to your code. If an agent's change goes wrong, you can go back to the last version that worked, so you can let it experiment without worrying about breaking something permanently.

Git also shows you exactly what the agent changed in each file, so you can check its work.

With Git, several AI agents can also work on different things in parallel, each on its own branch, and bring their work back together afterwards.

And if you can access your organisation's codebases, you can investigate your product or ask an agent questions about it.

Once you're comfortable with the command line, you can build tools and automations on your own computer for a much wider range of tasks than an AI chat assistant can handle.

The basics of databases are worth learning too. They let you prototype features, especially admin ones, without building a user interface for them, and read user metrics straight from the database or your analytics tools.

AI is good at writing SQL, so you don't need to learn it yourself. What you do need to learn is the right process for running the SQL snippets it generates in different situations.

Knowing the basics of these tools, without learning to code, is enough to check an agent's work and investigate your product without waiting for an engineer.

## 4

Technical Skills in the AI Era (4/5)

I promise you, understanding how AI agents work doesn't need maths beyond the level of a 9- or 10-year-old. It's mostly about how these systems are designed.

If you're a product manager or a startup founder handing work to AI agents, and you know what they're good at and where they struggle, you can plan how to get good results from them and build automations you can rely on.

For example, the model itself can only generate text. When an agent searches the web or edits a file, the model writes a request to use a tool, and the app around it runs the tool and sends the result back.

Memory works in a similar way. The model doesn't remember your previous conversations. The chat app or agent sends the relevant history and saved notes along with each message, and when a conversation gets too long, older parts get summarised or dropped.

Once you know this, you can see why an agent forgets something you told it an hour ago, and you can plan what information and tools to give it.

There's a lot more like this that's worth knowing: context windows and tokens, context rot, system prompts, why the same prompt can give different answers, and how MCP servers, skills and subagents extend what an agent can do.

This becomes even more useful once you move from asking questions in an AI chat assistant to building automations that need to work reliably.

I think the goal is to understand these systems well enough to make conscious decisions about how to use them.

## 5

Technical Skills in the AI Era (5/5)

Writing a detailed spec or PRD before you let an AI agent build anything feels like the responsible thing to do. I think it often works against you.

It means deciding everything up front, before you've seen anything working. Software engineering learnt this the hard way, and it's one of the reasons Extreme Programming (XP) and agile came about.

Many XP and agile principles work really well with AI agents, and product managers and founders can use them without writing any code. For example:

- Make one small change, test it, and only then move on to the next one.
- Decide how you'll check that something works before you ask the agent to build it.
- Get a simple version working end to end first, then improve it.
- Only build what you need right now.
- Tidy things up as you go, so they stay easy to change.

Each of these shortens the time between asking for something and finding out whether it works.

There's a lot more worth knowing from XP and agile: test-driven development, pair programming (including pairing with an AI agent), continuous integration, trunk-based development, feature flags and continuous learning.

They can feel unnatural at first, especially when an AI agent makes it so easy to ask for everything at once. You can try them on a small project and see the difference for yourself.
