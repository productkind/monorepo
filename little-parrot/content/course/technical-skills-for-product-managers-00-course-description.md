**Course descriptor:** A hands-on technical skills course for non-technical
software Product Managers.

## Value Proposition

### Make product decisions you can defend with technical evidence

You'll be able to trace how a software product works, follow a change through
testing and deployment, investigate issues, evaluate technical consequences
and test a bounded idea with artificial intelligence (AI), so you can
recommend scope and trade-offs before the team commits and involve engineering
with clearer evidence. You'll leave with an end-to-end product case study
containing a system map, application programming interface (API) and data-flow
trace, release walkthrough, bug
investigation, technical decision review, working prototype and production
handover.

## Course Description

When you cannot see how the parts connect, it's hard to use what engineers tell
you in a product decision. Throughout this hands-on course, you'll examine,
change, test, investigate and build on one software product.

You'll trace the frontend (what users see), backend (the product's logic and
services), database (where product data is stored) and APIs (the ways software
systems exchange requests and data). You'll follow a change through version
control (the recorded history of code changes), code review (when engineers
check a proposed code change), testing, staging (an environment used to check a
change before release) and deployment (the process that makes a software
change available to users).

You'll also reproduce and triage a bug (review its evidence and priority),
assess dependencies and technical debt (future work created by a technical
shortcut), and build a bounded working prototype with AI. You'll compare that
prototype with the testing, security, reliability, maintenance and ownership
required for software that a company operates for real users.

By the end, you'll be able to explain the evidence behind a product decision
and bring engineering a clearer recommendation, questions and handover. The
course prepares you to work more effectively with software engineers. It does
not train you to become an engineer or own production systems.

## What You'll Be Able To Do

- **Diagram how a web application works.** You'll be able to trace a user
  action through the frontend, backend, database, an API and an external
  system, so you can explain where a proposed change or problem appears.
  You'll leave with an end-to-end system and data-flow map.

- **Trace how software deployment works.** You'll be able to follow a change
  through version control, code review, tests, staging and deployment, so you
  can see what has happened, what evidence exists and what Product still needs
  to decide. You'll leave with a release walkthrough showing each stage and
  handover.

- **Investigate and triage a bug.** You'll be able to reproduce a problem,
  inspect requests and logs (records produced by software while it runs), and
  separate known facts from assumptions, so you can involve engineering with a
  useful starting point. You'll leave with a bug investigation and escalation
  containing reproduction steps, evidence and unanswered questions.

- **Evaluate technical debt and dependencies before commitment.** You'll be
  able to examine failure modes, reversibility, dependencies and technical
  debt, so you can recommend scope and trade-offs before the team commits.
  You'll leave with a technical product decision review containing the risks,
  options, supporting evidence and your recommendation.

- **Build an AI-assisted prototype and define its production boundary.**
  You'll be able to create and test a bounded working prototype, so you can
  gather evidence about an idea before asking engineering to build production
  software. You'll leave with a working prototype and a production handover
  covering testing, security, reliability, maintenance and ownership.

- **Present an end-to-end technical product decision.** You'll be able to
  connect the system, release, investigation, trade-off and prototype evidence,
  so you can lead a product decision with engineering. You'll leave with one
  complete case study that shows what you know, what remains uncertain and
  what you recommend.

## Scope Boundaries

This course helps generalist software Product Managers trace, inspect,
question, decide and prototype. It does not cover specialist machine learning,
data engineering, infrastructure, platform engineering, security engineering
or production software ownership.
